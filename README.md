# Auto Unwrap v3.0.3

Auto Unwrap v3.0.2 是一個 Windows x64 拖放式工具，專門處理「檔案內容是壓縮檔，但副檔名被偽裝成 `.jpg`、`.png`、`.lz4` 或其他名稱」的情況。此版本在 v2.0 的原地混合解壓基礎上，重新整理整體 UI、改善密碼選擇回饋、將固定輸出位置改為直覺的資料夾選擇器，並減少大檔案處理時不必要的 I/O。

## v3.0.3 自動刪除可靠性修正

v3.0.2 已有正確的「完成後自動刪除」流程，但 Windows 對剛完成解壓的檔案可能暫時回報 `ERROR_SHARING_VIOLATION`、`ERROR_ACCESS_DENIED`、`ERROR_LOCK_VIOLATION` 或 `ERROR_USER_MAPPED_FILE`，例如 Explorer 預覽、縮圖、Windows Defender 或索引服務仍持有檔案。v3.0.3 不再只呼叫一次 `DeleteFileW`：會先清除檔案屬性，最多重試 8 次並逐步增加等待時間；若 Windows 仍暫時鎖定檔案，最後會使用 `MoveFileExW(..., MOVEFILE_DELAY_UNTIL_REBOOT)` 登記重新啟動後刪除。已不存在的檔案也會視為清理成功，避免檔案在檢查與刪除之間被其他程序移除而產生假錯誤。

診斷紀錄新增 `attempts=`、`scheduled_on_reboot` 與 `scheduled_on_reboot=` 統計，可直接判斷是立即刪除、已排程重開機刪除，還是真正失敗。這個版本不會因為刪除失敗而刪除未完成或 CRC／checksum 有警告的壓縮檔；原有完整性安全條件保持不變。

## v3.0.2 自動刪除啟用驗證

你提供的最新診斷報告已確認：該次工作使用的是 `3.0.0-feature`，而且在處理開始及工作結束時都記錄 `完成後刪除：否`／`delete_after=no`。因此該次工作沒有啟用自動刪除；在工作完成後才於 20:26:23 切換勾選，不會回溯刪除已完成的工作。

v3.0.2 將版本識別更新為 `3.0.2-delete-fix`，並在拖放開始時固定保存本次工作設定。畫面及診斷紀錄會先顯示「本次工作已啟用」或「本次工作未啟用」，避免使用者在處理途中才勾選而誤以為會套用到目前工作。診斷事件 `JOB_START`、`DELETE_JOB_MODE`、`DELETE_SETTINGS` 及 `JOB_DONE` 都會記錄 `delete_after_for_job`。

請在開始拖放前開啟「輸出與刪除設定」，勾選「完成後自動刪除已成功解壓的壓縮檔」，按「確定」後再拖入檔案。開始處理後才勾選，只會影響下一個工作。

## v3.0.1 自動刪除修正

「完成後自動刪除已成功解壓的壓縮檔」現在會在設定確認後寫入 `%APPDATA%\\AutoUnwrap\\settings.ini`，並在啟動時讀回。診斷紀錄會記錄 `DELETE_SETTINGS`，確認當次工作使用的設定；每個可刪除的完整成功壓縮群組會記錄 `DELETE_QUEUE`。

v3.0.1 使用 Windows `DeleteFileW` 清理壓縮檔，刪除前會先清除唯讀、隱藏及暫存檔案屬性。單檔壓縮檔會刪除檔案本身；分割 7Z／ZIP／RAR 會刪除完整群組的所有卷。每個檔案都會記錄 `DELETE_RESULT`，最後以 `DELETE_SUMMARY` 統計要求、成功及失敗數量。

具有 CRC／checksum 警告的部分成功結果不會加入自動刪除清單；這是刻意的資料安全保護。若刪除失敗，程式會在畫面日誌顯示 Windows 錯誤碼，並保留原始檔案。

## v3.0 功能優化

### 響應式 UI

主視窗現在會在 `WM_SIZE` 事件中重新排列所有主要控制項。正常寬度下六個功能按鈕會排成一列；視窗縮窄時會自動改成兩列，日誌、進度列與狀態列會跟隨視窗寬度及高度伸縮。跨到不同 DPI 螢幕時會重建 Segoe UI 字型並重新套用版面，避免影片中出現控制項固定在左上角、右側和下方大面積空白的問題。

### 輸出與刪除設定記憶

輸出模式、固定輸出資料夾及「完成後自動刪除」現在會寫入 `%APPDATA%\\AutoUnwrap\\settings.ini`，並在程式啟動時重新載入。舊版分散的 `.dat` 設定仍保留作為相容 fallback。按下輸出設定視窗的「確定」後才會保存變更；按「取消」不會覆蓋原設定。

### 偽裝檔名規則

新增「偽裝檔名規則」視窗。對於 `XXXXX.rar請刪除文字後解壓` 這類檔名，可以保存 `請刪除文字後解壓` 作為規則，程式會先確認檔案內容確實是 RAR／ZIP／7Z／LZ4，再移除該文字並進入原有解壓流程。

程式也會自動處理正式壓縮副檔名後接自然語言文字的情況，例如 `file.rar請刪除文字後解壓`；但不會無條件把所有未知檔案改成壓縮檔。這是刻意的安全設計，可避免把正常遊戲資源、存檔或一般文件誤改名。若自動規則無法覆蓋你的命名方式，請在規則視窗加入固定附加文字。

## v2.9.1 分割檔密碼補充修正

最新診斷報告的版本仍是 `2.7.0-diagnostics`。其中第一層 `PC13338.7z.001` 正常解壓，但手動拖入後的 `PC13338.rar` 在所有既有候選失敗；v2.9.1 會在任何層級的既有候選全部失敗後要求輸入該層專用密碼，包括使用者手動拖入第二層檔案時的第 1 層。補充密碼只會重試該新密碼，不會重新讀取大型壓縮檔的所有舊候選；成功後會加入後續層候選。

Bandizip 與 7-Zip 的密碼參數格式分開處理：Bandizip 使用 `-p:密碼`，7-Zip 使用 `-p密碼`；不可把兩者語法混用。v2.9.1 也保留空密碼、密碼遮罩及完整工具輸出記錄。

## v2.9 速度與最終遊戲目錄修正

本版本根據 Windows 實際診斷報告修正四個問題。第一，7-Zip 解壓完成後，舊版仍會對全部 3,560 個輸出檔做內容掃描，並把正常的 APK、save、pyc 等檔案中的偶然 `PK` 位元組誤判為 ZIP；現在只有 JPG／PNG／LZ4／DAT／IMG／TMP／無副檔名等可疑偽裝副檔名才進行前 1 MiB 深度掃描，`.apk`、`.pyc`、`.save` 等正常遊戲資源不再深度掃描。

第二，若本層新產生的檔案中出現 `game`、`renpy` 目錄或任何 `.exe`，程式會寫入 `FINAL_GAME_MARKER` 並停止該遊戲樹的後續巢狀掃描。這符合本工具的實際用途：你指定的偽裝壓縮檔不會以 `.exe` 作為偽裝內容，而出現遊戲目錄／執行檔時通常已到最終檔案層。

第三，MoveTree 已經直接收集所有移交的檔案時，不再立即對整個輸出資料夾做昂貴遞迴回掃；只有直接清單為空時才使用回掃。解壓期間的暫存活動掃描間隔也由 5 秒調整為 15 秒，降低大檔案 I/O 競爭。

第四，巢狀層的既有密碼全部失敗時，程式會提示使用者輸入該層專用密碼，只重試新輸入的密碼，不會重新解壓大型檔案的舊候選；成功後新密碼會加入後續層候選。

## v2.8 診斷案例修正

本版本根據實際 Windows 診斷紀錄修正兩個核心問題。第一，7-Zip 在大檔案接近完成時可能輸出 `CRC Failed in encrypted file. Wrong password?`；其中 `Wrong password?` 是 7-Zip 對 CRC 失敗的通用提示，不代表密碼已被確定判錯。現在只要同時觀察到 CRC／checksum 失敗，就不再把該次嘗試當成明確密碼錯誤；若 exit code 為 2 但暫存區已有檔案，會以「部分成功／完整性警告」處理，移交可讀取結果、繼續掃描下一層，並保留原始壓縮檔不自動刪除。

第二，第一層成功後的下一層候選現在同時來自 `MoveTree` 直接回傳的檔案及輸出資料夾遞迴掃描結果，並使用統一路徑鍵值去重。這避免檔案交接時因相對／絕對路徑、大小寫或掃描時機造成 JPG 偽裝壓縮檔漏排。

## v2.7 診斷與辨識改進

本版本加入完整的本機診斷紀錄。程序會持久化記錄啟動、設定載入、拖放、密碼候選嘗試結果、解壓工具回傳碼、耗時、輸出量、CRC／校驗錯誤、遞迴層級、分割卷群組、檔案辨識、輸出位置、磁碟空間、記憶體、CPU、Windows 版本、DPI 及取消／完成事件。診斷紀錄位於 `%APPDATA%\\AutoUnwrap\\diagnostic.log`，主視窗新增「診斷／匯出報告」按鈕，可將目前診斷內容與系統摘要匯出為 TXT。

診斷功能**不會記錄密碼內容**，只記錄候選數量、密碼長度及 `password_value=REDACTED`。報告仍可能包含輸入檔案、輸出資料夾及解壓工具路徑，提交前請檢查是否需要遮罩私人路徑或檔名。

辨識流程改為依檔案內容判斷，不再只依附檔名；對 JPG、PNG、GIF、BMP、WEBP、LZ4、DAT、BIN、IMG、TMP 等可疑偽裝副檔名會深入掃描前 1 MiB，支援自解壓前置區或非標準副檔名。大型一般檔案仍先快速掃描，避免對整個遊戲輸出造成不必要 I/O。

大檔案處理會把 Bandizip／7-Zip 的完整輸出分類為密碼錯誤、CRC／校驗錯誤、一般工具錯誤或部分成功；若 exit code 2 但已有輸出且沒有明確 `Invalid password`，會保留部分結果並在日誌中標記，不再直接宣稱密碼錯誤。

## v2.6 改進摘要

本版本修正三個核心問題。第一，分割檔解壓後的 JPG 偽裝壓縮檔現在會被自動發現並改名解壓，不再只依賴 `changed_files`。第二，大檔案解壓到一半被誤判密碼錯誤的問題已修正：若 Bandizip 回傳 exit code 2 但已有大量檔案成功解壓且沒有明確的 `ERROR: Invalid password`，程式會視為「部分成功」並保留結果。第三，提供 Windows 實機驗證方案，讓使用者可以在自己的電腦上直接測試 Bandizip `bz.exe` 的行為。

## v2.5 改進摘要

本版本修正三個核心問題。第一，Bandizip 密碼參數改為直接 `-p:password`，不再加額外引號，避免特殊字元或非 ASCII 密碼被錯誤解析。第二，第一層成功後會遞迴掃描整個輸出資料夾中本次新增的檔案與目錄內容，確保第二層壓縮檔被自動發現，不再只依賴 `changed_files`。第三，分割檔群組解析現在支援非主卷入口（如 `.002`、`.z01`、`.r00`），只要主卷存在且可辨識，就會接受並使用主卷解壓。

對 5.5G 大檔案，若密碼已開始解壓但最後在 CRC 驗證階段失敗，程式會在日誌中明確標示「密碼可能正確但 CRC 驗證失敗」，並建議檢查分割卷完整性或改用 7-Zip 交叉驗證。

## v2.4 改進摘要

本版本修正兩個會使核心功能失效的問題。第一，程式不再把 `Bandizip.exe` 圖形介面入口當成自動解壓引擎；若選取 Bandizip，會優先改用同目錄的 `bz.exe` 主控台程式，找不到時才尋找 7-Zip 備援，因此不會由 Bandizip 彈出互動式密碼輸入視窗。第二，程式不再把 `PC13338.7z.001` 改成 `PC13338.7z.7z`，而是把所有分割卷視為一個完整群組，以正確主卷解壓。

密碼視窗按下「確定並使用」時會使用輸入框當下的文字。點選清單密碼會同步填入輸入框；若使用者之後手動修改密碼，新的手動輸入不會再被舊的清單選取覆蓋。

## v2.3 改進摘要

本版本針對第一層解壓長時間沒有輸出、使用者無法判斷是否卡住的問題，重新處理 Windows 子程序生命週期。程式不再使用無限等待，也不再丟棄 7-Zip／Bandizip 的工具輸出；解壓期間會顯示目前層級、密碼候選、耗時、工具百分比及暫存輸出大小。空密碼候選也會明確傳入密碼參數，避免 7-Zip 進入互動式 `Enter password` 提示而等待。

## v2.2 改進摘要

本版本特別修正高 DPI 螢幕上的文字過大與控制項截斷問題。程式會在啟動時啟用 Windows Per-Monitor DPI Awareness V2，並使用以 96 DPI 為基準的座標與字型縮放；同時會根據目前螢幕工作區自動縮小基準 UI，避免 150% 或 200% 顯示比例下主視窗高度超出螢幕。若視窗被移到另一個 DPI 不同的螢幕，主視窗會收到 DPI 變更事件並採用新的建議尺寸。

| 輸出掃描 | 不再對整個輸出資料夾建立前後快照，只掃描本層暫存解壓結果，避免輸出資料夾已有大量遊戲檔案時反覆遞迴掃描。 |
| 進度回饋 | 解壓大型檔案時顯示動態進度列及「大型檔案會直接串流解壓」狀態；實際百分比仍由 Bandizip／7-Zip 內部處理。 |

## 使用方法

首次啟動程式時，若畫面提示選擇解壓縮軟件，請選擇 Bandizip 安裝目錄內的 `bz.exe`；不要選 `Bandizip.exe` GUI 入口。若希望使用 7-Zip，請選擇 `7z.exe` 或 `7zz.exe`。主視窗右上方會顯示目前完整工具路徑，按「設定解壓工具」即可重新選擇。

按「密碼管理」後，在上方輸入框輸入密碼。按「加入常用」後，該密碼會出現在清單中。點選清單中的一列時，整列會以藍色反白並顯示黃色識別條，同時下方會顯示「目前選擇」的實際密碼。這個明確的選取狀態代表密碼已填入輸入框；按「確定並使用」後，會使用輸入框當下的文字。若之後手動修改輸入框，則以手動修改後的文字為準。密碼內容依照你的要求以明碼顯示；請避免在他人可以看到畫面的環境開啟此視窗。

按「輸出與刪除設定」後，可以選擇三種輸出模式。使用「原始檔案所在資料夾」時，所有解壓內容會回到拖入檔案的資料夾。使用「固定輸出資料夾」時，點選該選項或「瀏覽」按鈕，會開啟 Windows 資料夾選擇器，直接以檔案管理方式選擇資料夾。使用「每次處理時詢問」時，每次拖放檔案都會先選擇目的地。

同一個設定視窗也提供「完成後自動刪除已成功解壓的壓縮檔」。勾選後，只有已成功解壓的壓縮檔才會刪除；錯誤密碼、解壓失敗或無法移動的檔案會保留。刪除動作是直接刪除，不會移到資源回收筒，因此建議先以關閉此選項的方式確認輸出內容。

設定完成後，把偽裝檔案拖到主視窗。程式會讀取檔案內容的魔數，不信任原始副檔名，直接將檔案在來源位置改成 `.rar`、`.zip`、`.7z` 或 `.lz4`。每一層會在輸出目的地建立隱藏暫存資料夾，逐一用密碼執行解壓；錯誤密碼的暫存結果會刪除，正確密碼成功後才會把結果移入輸出資料夾。

## 混合多層範例

以下流程可由新版逐層處理：

```text
download.rar                 ← 一開始就是 RAR，直接改名後解壓
└─ picture.jpg               ← 內容其實是 ZIP，改成 picture.zip
   └─ another.jpg            ← 內容其實是 7Z，改成 another.7z
      └─ game files...       ← 最終真實檔案
```

每一層都會重新讀取格式與重新嘗試密碼，因此外層 RAR 使用 `Pass1`、中層 ZIP 使用 `Pass2`、內層 7Z 使用 `Pass3` 時，只要三組密碼都已輸入或保存，流程不會把所有層錯誤地當成同一種格式。程式最多自動處理 5 層，以避免循環檔案或異常巢狀造成無限處理。

## 第一層卡住問題與取消方式

舊版在等待解壓工具時會丟棄 stdout／stderr，並且使用無限等待；如果錯誤密碼後進入互動式密碼提示，或大型 RAR 正在長時間解碼，畫面只會停在「直接嘗試密碼」。v2.3 已改為非阻塞輪詢子程序，將 stdin 綁到 `NUL`，不允許工具等待人工輸入；同時把最後一段工具輸出寫入日誌。若狀態列顯示工具百分比或輸出活動大小正在變化，代表仍在工作。

解壓開始後，狀態列會顯示目前層級、密碼候選、經過時間、工具百分比及暫存輸出大小。超過 10 分鐘沒有活動時，程式只會提示「仍在等待」，不會立即終止；超過 30 分鐘完全沒有工具輸出及檔案活動才會終止子程序。若要手動停止，可以關閉主視窗並確認「取消並關閉程式」。取消時未完成的壓縮檔會保留，不會自動刪除。

## 1–50G 大檔案處理說明

你提供的檔案大小資訊非常有幫助。新版特別移除了兩個對大檔案不利的步驟：第一，不再先使用 `t` 完整測試壓縮檔、再使用 `x` 完整解壓同一檔案；第二，不再針對輸出資料夾全部內容建立前後快照。現在每一個密碼候選會直接嘗試解壓到同一輸出磁碟的隱藏暫存資料夾，找到正確密碼後直接使用結果，錯誤嘗試會清理。

這可以減少正確密碼情況下的一次完整讀取／解碼，也可以避免輸出資料夾已有數十 GB 遊戲檔案時的全目錄遞迴掃描。成功後若暫存資料夾與輸出資料夾位於同一磁碟，程式會優先使用 rename／移動目錄項目的方式交付結果，不會再次複製整個 50G 檔案。若檔案系統不允許直接移動，才會退回複製方式。

實際速度仍取決於壓縮演算法、CPU、來源與輸出磁碟的讀寫速度、密碼加密方式、解壓工具版本以及可用空間。若來源檔案和固定輸出資料夾位於不同磁碟，移動目錄項目可能需要實際複製資料；對 50G 檔案而言，建議把固定輸出資料夾設在與來源相同的磁碟，以提高成功後交付速度並避免額外複製。

## 重要限制與安全提醒

目前程式辨識 ZIP、7Z、RAR4、RAR5 和 LZ4 的檔案簽名。若 `.lz4` 只是偽裝副檔名而內容實際是 RAR、ZIP 或 7Z，會依真正內容處理；若內容確實是 LZ4，能否解壓取決於所選 Bandizip 或 7-Zip 版本的支援情況。程式不會自行下載第三方解壓工具，也不會嘗試破解或暴力搜尋未知密碼。

原地改名的目的，是讓你可以直接看到每一層的真實副檔名。若同名正確副檔名已存在，程式會使用 `_2`、`_3` 等尾碼，避免覆蓋既有檔案。大型檔案處理時請確保輸出磁碟有足夠可用空間，並避免強制關閉視窗。

直接解壓來自網路的遊戲檔案前，請先確認來源可信並使用防毒軟體掃描。解壓工具本身仍可能遇到特殊檔名、符號連結、超大檔案或格式損壞等情況。

## 建置與測試

本專案使用 MinGW-w64 交叉編譯器製作 Windows x64 GUI EXE。Linux 建置指令如下：

```bash
sudo apt-get install g++-mingw-w64-x86-64
./build_mingw.sh
```

輸出檔為 `dist/AutoUnwrap.exe`。程式不內嵌 Bandizip 或 7-Zip，使用者必須自行安裝其中一個解壓工具；如此可避免重新散布第三方工具、版本及授權問題。

測試資料包含外層 7Z、內層 ZIP、再內層 7Z 的混合巢狀案例，並驗證三組不同密碼、錯誤密碼拒絕、直接改副檔名、原地輸出、成功後刪除，以及大型檔案友善的暫存嘗試清理流程。RAR4／RAR5／ZIP／7Z／LZ4 魔數辨識也已納入回歸測試。
